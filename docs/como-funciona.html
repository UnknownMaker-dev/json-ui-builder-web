json-ui-builder-web · funcionalidades portadas

Do canvas ao JSON UI do Minecraft, em um fluxo só.

Você desenha a tela arrastando componentes; a árvore reativa (Pinia) é a fonte de verdade; e um conversor transforma essa árvore no formato JSON UI do Bedrock — além de gerar o script do addon e reimportar arquivos. Este é o passo a passo de como cada peça se encaixa.

O fluxo em três estágios

Toda a ferramenta gira em torno de uma única conversão. Você opera o estágio da esquerda; a store guarda o do meio; a exportação produz o da direita.

ESTÁGIO 01

Desenho (Canvas)

Arrastar, redimensionar e aninhar componentes. Posições em pixels absolutos.

ESTÁGIO 02

Árvore (Pinia)

Cada componente é um UIElement com children. Estado único e reativo.

ESTÁGIO 03

JSON UI (Export)

Percorre a árvore e emite o .json do Minecraft, com escala de coordenadas.

canvas ⟶ árvore de UIElement ⟶ JSON UI · (e o caminho inverso na importação)

Como usar — passo a passo

  1. Adicione um container raiz

    Na barra lateral esquerda, clique em Panel (ou Stack / Collection / Scrolling). O primeiro elemento precisa ser um container — ele é a raiz da tela.

  2. Monte a hierarquia

    Com um container selecionado, adicione Button, Label ou Image dentro dele. Arraste no canvas e use os 8 handles para redimensionar. O Explorer mostra a árvore.

  3. Escolha texturas

    No painel direito, clique no quadro de textura para abrir o seletor visual: navegue pelos 5 presets ore-ui, busque por nome, ou envie um PNG + JSON próprio (guardado localmente). Botões têm texturas de estado (default / hover / pressed).

  4. Ajuste propriedades e bindings

    Edite texto, fonte, alinhamento, cor, nineslice e tamanho. No colapsável Bindings, ligue propriedades a dados dinâmicos do Minecraft (view / collection / global).

  5. Defina o namespace e gere o JSON UI

    No topo, ajuste o Namespace e clique em Gerar JSON UI. Abre um modal com o código; copie ou baixe o .json.

  6. Gere o script e o server_form

    Os botões TS / JS geram o addon @minecraft/server-ui com um form.button() por botão desenhado. server_form gera o wrapper de diálogo.

  7. Reimporte quando quiser

    Importar lê um .json gerado aqui (com o bloco config) e reconstrói a árvore no editor — o caminho inverso completo.

O que ficou de fora, de propósito: autenticação client-side e o "banco" sql.js do original. Eram infra falsa (sem backend real, sem segurança) — substituímos o único uso que importava, o upload de texturas, por armazenamento local direto.

O detalhe que faz tudo funcionar: coordenadas

O editor pensa em pixels absolutos (canto superior esquerdo). O Minecraft pensa em âncora + offset com unidades próprias. A ponte é uma multiplicação: todo elemento sai ancorado em top_left e tem seu offset e tamanho multiplicados por UI_SCALAR (0.36). Labels recebem uma correção extra de fonte. Como esses "números mágicos" vão embutidos no arquivo, a reimportação consegue desfazer a escala com fidelidade. 

// exporter — o coração da conversão
offset: [ p.x * UI_SCALAR, p.y * UI_SCALAR ],
size:   [ p.width * UI_SCALAR, p.height * UI_SCALAR ],
anchor_from: "top_left", anchor_to: "top_left",
// botões referenciam um template herdado:
"play@custom_form.custom_button": { $button_size: [...], ... }
